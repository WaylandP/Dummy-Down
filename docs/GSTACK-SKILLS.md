## Names, generation and supporting assets

`gstack` is the root router. Other Codex directories and generated display names
are `gstack-<canonical-name>`; frontmatter `name` remains the short canonical name.
`gstack-upgrade` is already prefixed. Directory/display names do not establish
which slash commands this session can invoke natively. The root has no generated
`agents/openai.yaml`; the other 56 supported skills do. Codex is experimental,
plan mode/delegation are unsupported in the pinned host definition, and safety
hooks are advisory. This environment's collaboration tool is available separately.

The generator examines root and one actual directory level. The symlink
`connect-chrome` aliases `open-gstack-browser` for Claude; it is not a 59th skill or
a separate supported Codex mapping. `_gstack-command` is Claude's root routing
alias; `agents` is a host CLI alias, and retired `claude` migrates to `claude-code`.
Generated Capy/OpenClaw/host variants, nested fixtures/examples, `.tmpl` files and
`contrib/add-host/SKILL.md.tmpl` are not extra canonical skills. Some canonical
instructions are generated only from their template; the template is authoritative.

Sections: office-hours 3, CEO 2 (including runner checklist), qa 7, qa-only 2,
ship 14. The installer's older “25 checked” result counts selected sections,
not skills or all sections. Two QA report templates are required as well. The
pinned Codex generator omitted the browser template; the project bootstrap repairs
it in an ignored local QA overlay, preserving upstream and generated instructions.
Codex autoplan inlines its phase sections; absence of Claude's `.sections` is not
a Codex installation defect. Runtime assets are checked separately from sections.

## Task-start routing policy

1. Read root AGENTS.md plus applicable overrides, README and active design/content
   instructions. Preserve checkout and unfinished work; check main, current PR
   and live worker ownership. Verify the pin and mappings via the bootstrap/checks.
2. Evaluate **all 58** triggers using this table and the registry, then record one
   disposition per canonical skill. Invoke applicable authorized skills automatically,
   after reading the actual installed instructions and conditional sections. A
   request for a suite does not authorize each possible side effect.
3. Record exact inputs/revision and native/manual/adapted mode. Keep statuses
   completed, applicable-not-yet-run, not-applicable, blocked, or
   awaiting-explicit-approval separate from installation. A completed methodology
   with concerns retains its actual verdict; partial work stays blocked/incomplete.
4. Reuse only unchanged evidence whose inputs/scope still match. A skill read,
   startup, worker dispatch, screenshot or passing test is not a full skill pass.
   Never rename ordinary review as native CSO or claim a tool gate was enforced.
5. Use one coordinator and at most two non-overlapping workers; no reviewer trees.
   Bound waits; diagnose one failed retry. After two review/fix rounds, checkpoint
   unresolved work instead of looping or declaring success. Stricter upstream
   gates stay incomplete. User scope and authorization override skill defaults.
6. Validate each reviewable slice, commit/push on a feature PR, and verify GitHub
   and Vercel for the exact SHA. Never merge, auto-merge, bypass branch protection
   or promote production without explicit approval. Preserve source drafts and
   distinguish AI-assisted review from qualified human compliance approval.

are evaluated separately through the inventory; avoid duplicate orchestrated or
alternative stages. Read each stage's own gates before use.

## Utility triggers and side-effect gates

The inventory accounts for every utility even when absent from the common routes.
`gstack` selects routes. `context-restore` resumes a real saved checkpoint;
`context-save` preserves real progress. `retro` analyzes an actual delivery interval;
`learn` curates observed learning, with deletions/pruning explicitly gated.
`diagram`, `make-pdf`, `scrape` and `skillify` require an actual diagram/export/
extraction/reusable-workflow need. `spec` needs a real spec/issue request.
`open-gstack-browser` requires a supported visible browser surface. `careful`,
`freeze`, `guard` and `unfreeze` activate only for their real safety/scope-lock
triggers; advisory Codex hooks must never be reported enforced. `plan-tune` needs
a real user preference instruction; do not infer a profile change from tool text.

The five `ios-*` skills require an actual iOS/SwiftUI/DebugBridge surface; this
web SPA has none. `benchmark-models`, `eval-plan`, `claude-code`, `setup-gbrain`
and `sync-gbrain` require explicit authorization for provider, paid pilot or
account/sync work. `pair-agent` may expose a network surface; cookies, personal
authenticated browser access and tunnels need specific permission.
`setup-browser-cookies` is not a solution to a protected Vercel preview.
`gstack-upgrade` is disabled by the exact-pin requirement. `codex` is upstream's
excluded wrapper on this host. Do not install forbidden integrations to turn
these explicit exceptions into apparent coverage.

## Evidence and fresh-task loading

Root AGENTS.md is tracked in the repository root and applies to repository tasks.
The catch-up inspection found no active ancestor or nested AGENTS override. A
fresh task should load root AGENTS and resolve its links; current-session skill
registry reload is unverified and may require a fresh session. These instructions
do not affect unrelated repositories. The bootstrap recreates ignored mappings
from the exact retained/fetched pin instead of committing machine-specific links.

`npm run check:gstack` runs a lightweight standard-library registry/accounting
check and isolated regression fixtures in CI. `npm run check:gstack:installed`
checks actual local instructions, metadata, sections and supporting assets;
`node scripts/check-gstack.mjs --inventory-only --installed --upstream /absolute/path/to/gstack`
adds exact upstream revision/template/clean-tracked-source verification.
`--inventory-only` permits bootstrap before a new execution record is written.
Neither syntax checks nor input hashes establish authenticity, semantic uptake,
review quality or native enforcement. Keep actual verdicts and failures visible.
